# v0.18 integration

The v0.18 prototype integrates original streamed render assets and collision
queries into native gameplay. It remains an incomplete asset-based port with
provisional handling and chase-camera motion. See ROCKPORT-PROTOTYPE.md for
installation, controls and exact limits. No public GitHub release is implied by
creating the private downloadable ZIP.

The scene archive includes 13,556 models (18 authored empty models), 997 source
sections plus one explicit boot-global provider bank, and 2,706 texture payloads.
Original normal-context LOD components select source bound slots; special view
state producers and full original streaming scheduling are incomplete.
The renderer retains floatRGB36 GPU vertices, original index order and source
material spans. Model/texture hash hints validate full identities before use;
known generation-checked slots avoid repeated cache-wide scans. Immutable
adjacent material spans are decoded once rather than per frame. Exact unchanged
camera/context/region views reuse their completed draw plan.

Runtime original collision activation consumes the renderer's exact source
section IDs. All three world files must share the original source SHA256.
Ground and centreline wall queries feed the provisional controller; this does
not substitute for the separately recovered compound-body impulse simulation.
If collision activation fails after a renderer stage, the driving world is not
presented as playable. Reset/menu remains available. Ordinary map-stage failure
retains the old complete camera/vehicle/world view and pauses further IO.

HUD rendering uses a persistent normal-RAM RGB565 canvas and one 512x256 tiled
RGBA8 GPU texture (512KiB). A point-sampled Citro2D quad presents complete dirty
updates through a linked bottom render target. The GPU completion queue owns
both LCD swaps; gameplay never writes a display framebuffer directly. Before
texture replacement, FrameSync fences its prior GPU readers. Every dirty draw
clears both colour and depth: Citro2D screen targets include a depth buffer,
whose uninitialized contents must never mask HUD labels. The opaque HUD pass
also disables inherited 3D alpha/depth tests explicitly. Unchanged HUDs do
not upload or redraw the bottom target. A portable texture codec test checks
all 131,072 texels, channel conversion, orientation, padding and bounds.

Emulator acceptance checks measure static HUD label regions across driving,
resets and loading failures, as well as idle menus. Enlarged captures and pixel
checks complement visual inspection at the 3DS display's native resolution.
Physical LCD behaviour still needs hardware confirmation.

Validation covers native ASan/UBSan real-source renderer/collision/controller
runs, rollback/fault injection, archive header/index/payload CRC and identity,
scene-normal acceptance and UI bounds/menu actions. Emulator smoke testing and
package verification are recorded separately under docs/progress. Component
original-executable parity reports remain in research; those reports do not
establish whole-car/game fidelity or stock hardware performance.
