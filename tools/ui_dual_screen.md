# Dual-screen UI

v0.17 integration is complete in `source_rockport/rockport_main.c` and the
explicit build script. Strict ARM link, host sanitizer checks and emulator
touch/menu/drive/garage/HELP/STATS checks pass. Runtime captures and evidence:
`/workspace/port-research/rockport/v0.17/validation.json`. Physical hardware
performance remains unmeasured. The integration contract below documents the
module boundary and the original first-pass handoff.

The v0.18 UI extension adds a DISPLAY page with a large `PISS FILTER`
ON/OFF toggle. `MwUiModel.piss_filter=false` displays OFF / NEUTRAL COLOURS;
true displays ON / OPTIONAL WARM GRADE. The module reports toggle intent only;
root owns the actual rendering effect and controller behavior. This extension
passed strict host sanitizer checks and pinned ARMv6K object compilation;
runtime integration is tracked separately from the v0.17 checks above.

New interface: `MW_UI_DISPLAY`, `MW_UI_SELECT_DISPLAY`,
`MW_UI_TOGGLE_PISS_FILTER`, and model `bool piss_filter`. Existing enum values
are preserved by appending the additions. Menu order is explicitly
DRIVE/GARAGE/CONTROLS/DISPLAY/QUIT (indices 0..4); touch actions use a lookup
table, not enum arithmetic. Root must update keyboard navigation to five rows,
map the Display Screen to `MW_UI_DISPLAY`, handle A as toggle in that screen,
and B/START or touch BACK as menu. Apply `MW_UI_TOGGLE_PISS_FILTER` once per
KEY_TOUCH down, update the model and request redraw.

Menu hit boxes are x=[12,308), y=[54+24*i,75+24*i) for i=0..4. The Display
toggle row is x=[12,308), y=[70,122). Footer BACK retains x=[6,314),
y=[208,236). All gaps and exclusive boundaries are checked by the host tool.
Previews: `/workspace/port-research/ui-dual-screen/v0.18-display/`.


This is a new 3DS layout, not a reconstruction of the original frontend.
The optional converted artwork now uses the supplied GameCube MW_LOGO,
FONT_MW_BODY, FONT_MW_TITLE and WS_MWSPLASHBACK artwork. Original FNTG glyph
coordinates, offsets and advances are read directly; kerning remains unapplied.
Uppercase/digit title glyphs are losslessly copied into a compact atlas; body
atlas is preserved. The source-art composition, layout, touch interactions,
angle and colors of selection bars are a 3DS adaptation. No recovered frontend
animation, racing HUD, pursuit meter or tachometer is claimed.

`tools/ui_build_assets.py GLOBALA GLOBALB FRONTB FRONTB_VM_NGC ui.nui` creates
the NUI2 sidecar using the existing offline texture decoder and Pillow.
The actual supplied/decompressed source files are required, not PC assets.
The JSON sidecar records source SHA256, texture hash/decoded-pixel SHA256 and
all used metrics. Concrete output and previews live at
`/workspace/port-research/ui-dual-screen/v0.18-original-art/`.

NUI2 is 328968 bytes. Its header pins version, total size, atlas dimensions,
counts and offsets; CRC32 covers the complete payload. Decoder checks table
uniqueness, required ASCII and title characters, glyph/advance/offset bounds
and atlas regions before allocating. It owns one bounded allocation (~331.5KB)
with no render-time allocation. Pass `MwUiModel.assets=NULL` for the built-in
fallback. Free the source file buffer after `mw_ui_assets_decode`; keep the
returned context alive through rendering and free at shutdown. This does not
add a dependency or image decoder to the 3DS runtime.

## Arrangement

- Top 400x240: keep the existing unobstructed driving/car view.
- Bottom 320x240: large speed readout; original-road navigation map; persistent
  loaded-map boundary warning; discrete MENU, HELP and STATS touch buttons.
- HELP and STATS replace only the map panel. They do not pause, reset, or alter
  driving. Button controls remain the primary way to drive.
- Menu: five touch rows, with controller selection retained.
- Garage and controls: bottom-screen bindings and back button; top stays useful
  for viewing the car. No fake unsupported frontend features are presented.

The current 152x128 map size is retained so map generation work and the existing
RGB8 map buffer do not grow. No new map is generated by the UI. The preview uses
the existing v0.16 road-map output. The preview's speed/counters are illustrative
inputs; they are not hardware measurements or readings from its top screenshot.

## Integration contract (root-owned runtime)

Add `mw_ui.c` to the explicit CFILES in `tools/build_rockport.sh`; include
`mw_ui.h` in main. Do not rely on the default Makefile wildcard because this
build script overrides it. Existing main/build files are intentionally untouched.

Keep console initialization and the current error text path. For successful
initialization, replace console `status` / `navigation_status` writes with the
new renderer. Mixing console output with the new framebuffer will corrupt UI.

Maintain `MwUiPanel panel=MW_UI_NAVIGATION` outside the frame loop. Build a model
from the existing Screen, selected item, DriveState, edge status and counters:

```c
MwUiModel ui={
    .mode=screen==MENU?MW_UI_MENU:screen==DRIVE?MW_UI_DRIVE:
          screen==GARAGE?MW_UI_GARAGE:MW_UI_CONTROLS,
    .panel=panel,.selected=selected,.speed_mps=car.speed,
    .handbrake=screen==DRIVE && (held&KEY_R),
    .road_status=edge?MW_UI_EDGE_REACHED:MW_UI_ROAD_LOADED,
    .fps=measured_fps,.triangles=world_triangles_drawn,
    .draw_calls=world_draw_calls,.gpu_ms=C3D_GetDrawingTime(),
    .draw_ms=C3D_GetProcessingTime(),.logic_ms=simulation_ms,
    .slip_degrees=atan2f(car.lateral_speed,
                       fmaxf(fabsf(car.speed),.01f))*57.29578f
};
if (!edge && road_edge_ahead(&road,&car,height))
    ui.road_status=car.speed<0?MW_UI_EDGE_BEHIND:MW_UI_EDGE_AHEAD;
```

Render the existing RGB8 map only when driving with the navigation panel shown.
`mw_ui_render` expects exactly 152x128 packed RGB8, matching current `map_rgb`.
Pass null when unavailable or unused. Keep the existing successful framebuffer
checks: `gfxGetFramebuffer(GFX_BOTTOM,GFX_LEFT,...)`, width240, height320,
format `GSP_RGB565_OES`, byte capacity `width*height*2`. Call:

```c
(void)mw_ui_render(framebuffer,(size_t)width*height_px*2,&ui,map_or_null);
```

Retain the existing single-buffer bottom-screen setup and gfxFlushBuffers path.
Update at the existing 200ms navigation cadence, immediately on transitions,
selection changes, touch-panel toggles and reset; handbrake state changes can
also request immediate redraw. There is no requirement to redraw at 60Hz.

On **KEY_TOUCH down** only, call `hidTouchRead` and `mw_ui_touch`. Do not call
it for every held-touch frame, which would toggle panels repeatedly. Handle
OPEN_MENU with existing menu behavior. SELECT_DRIVE/GARAGE/CONTROLS/QUIT select
the named state. TOGGLE_HELP/DIAGNOSTICS toggle their panel against NAVIGATION
and request redraw. Do not route HELP through the existing CONTROLS state:
that would take the user out of the drive session. This module reports intents;
it deliberately does not mutate game state or read SDK input.

Existing menu-to-drive behavior resets the car. This change need not alter that
behavior, but future pause/resume should be explicit and preserve DriveState,
wheel, road-pose and chase-camera state together.

## Cost and verification

- No render-time allocation. Optional art is decoded/copied once at startup.
- No new dependency, texture, shader, GPU draw call or Citro3D state change.
- Writes the existing RGB565 framebuffer directly; full background is 153600
  bytes, plus panels/text/map writes. No additional full-screen staging buffer.
- Existing map generation and storage stay unchanged.
- Full redraw at 5Hz is a first-pass policy, not a measured hardware timing win.
- Host strict C11 build + ASan/UBSan passed framebuffer guard, undersized-buffer
  rejection and touch target/gap/boundary checks.
- ARMv6K hard-float object compiled with the pinned devkitARM image using
  `-O2 -Wall -Wextra -Werror`. This is not yet a linked/runtime emulator test.

Reproduce host previews:

```sh
cc -std=c11 -O2 -Wall -Wextra -Werror -fsanitize=address,undefined \
  -Iinclude tools/ui_preview.c source_bmw/mw_ui.c -lm -o /tmp/ui-preview
/tmp/ui-preview /workspace/port-research/rockport/v0.16/map-reference.ppm \
  /workspace/port-research/ui-dual-screen/v0.18-original-art \
  /workspace/port-research/ui-dual-screen/v0.18-original-art/ui.nui
```

The nine output PPMs are rendered by production UI C code. PNG conversions and
`dual-screen-design-preview.png` are saved in that research directory. The latter
is explicitly labeled: existing captured top view plus proposed bottom UI.
Runtime integration and emulator menu/touch checks were completed for v0.17;
stock-hardware cost remains unmeasured.
