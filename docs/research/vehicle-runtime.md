# Source-native vehicle runtime composition

`mw_vehicle_runtime` composes the recovered engine, steering, complete player
wheel routing, aerodynamic forces, four-wheel contact dynamics and rigid-body
numerical modules. It returns the actual body state, not a bicycle controller or
direct yaw/position approximation. It is **gated integration infrastructure**, not
a demonstrated complete 1:1 vehicle implementation and is not enabled in the app.

## Original order

Matching debug ELF and unchanged original instruction inspection establish:

* The source scheduler's SimStart priority0 calls rigid-body Update: all body
  OnBeginFrame integration, collision processing, then OnEndFrame.
* Vehicle Physics tasks priority3 run input, EngineRacer, SuspensionRacer in
  actual ascending behavior priority. The physical source step is1/60 second;
  scheduler update fraction is not a duration.
* Consequently wheel/aerodynamic forces generated by the current vehicle task
  are integrated in the next SimStart interval.

Runtime invokes required `before_body_tick`, original integration,
`after_body_tick`, then producer, engine, steering and suspension. Those body
hooks must implement the real original primitive refresh, flags, force reset,
gravity seed, world collision, sleep and end-frame behavior in their proper
phases. They are required callbacks, never silently assumed empty. The trial
state is copied locally and committed only after all stages succeed. Callback
contexts must similarly stage external state until success.

Aerodynamics emits drag then downforce at original transformed world points.
These call the recovered body AddForceAtWorldPoint. Complete TuneWheelParams
emits original AddTorqueWorld and an optional **IPlayer::ChargeGameBreaker**
command. Charge is retained in successful output for the gameplay owner to apply
once, after commit; it is not misinterpreted as a rigid-body command.

Four wheel forces/moments are not independently submitted as body forces.
Original DoWheelForces sums them, shapes the projected yaw torque using
TIRES.YAW_SPEED, submits a combined world wrench, then performs bottomout and
landing suffixes. `mw_vehicle_runtime_chassis_commands` now implements that late
phase and was compared against1638 unchanged original late-function cases. The
runtime applies the resulting world wrench, raises body/wheel position for maximum
penetration, and applies the original landing angular-velocity command. Landing
means new contact count>0 with previous count0; local angularY/Z are halved then
rotated to world. Body angular setter is a plain XYZ copy with no wake side effect.
The command comparison supplies the already summed forces/moments at the original
boundary; earlier contact/moment stages have their own comparisons.

## Explicit providers and numerical gates

The required producer mask records whether the caller supplied recovered engine,
player, route, mechanical, differential and scheduler producers. The producer
runs after SimStart. Runtime replaces only recovered source body/raw/wheel
fields: body matrix/velocity, inertiaY, local velocity/slip, physical wheel mount
positions, old wheel contact/slip, engine torque and physical transmission split.
Other interface/state/tuning fields must be supplied explicitly. A set bit is a
caller assertion, not a numerical verification.

Steered directions default to the compared original trigonometry/body rotation
producer. Suspension defaults to the compared positive0..2 original power kernel;
contact defaults to compared original sine. Optional overrides remain explicit;
invalid power results reject transactionally. Mechanical power
uses the separately verified native original positive sqrt/square branches by
default. Original player gamepad mode0, default Handling1, null/zero tunings and
zero initial GameBreaker/CollisionTimer are source-backed, but later dynamic
providers cannot be frozen to their initial values.

Manual gear requests reject until original policy/side effects are integrated.
Nonempty engine speed-limiter arrays still reject. All six exported stock
profiles have empty arrays. The complete engine entry point now includes original
timed turbo/supercharger induction, while legacy entry points intentionally keep
their disabled-induction-only contract. The producer supplies the current optional
Tunings.Value[18], rather than freezing it to the constructor value.

## Source parameter sidecar

`tools/build_vehicle_runtime.py` emits NVR1 version2,1084 bytes, CRC32 over bytes
16..end. It validates exact original ATTRIBUTES, Speed.dol and collision-bank
SHA256. Explicit per-component upgrade indices are mandatory. Physical mass,
TENSOR_SCALE, root signed-short extents, local CG and gravity come from original
source provenance, never visual bounds. Sidecars stay private.

Layout: header128; nested NDP1 wheel profile336; nested MMP1 mechanical
profile156; body64; engine128; bounded torque16, braking16, gear10,
efficiency10 and yaw16 float arrays. The loader validates nested source digests,
CRC, keys, finite values, counts and zero padding, computes original inertia and
startup shift/peak-torque tables, then rebinds internal pointers. The parameter
object must remain at a stable address while used. Version2 uses previously
reserved engine bytes36 (PSI),120 (SPOOL_TIME_UP) and124 (SPOOL_TIME_DOWN).
Version1 remains readable for disabled-induction profiles; active-induction
version1 profiles reject because their required timing was never packed.
Updated private sidecars are under `/workspace/port-research/driving-runtime-v2`.

Six profiles exported: m3gtre46careerstart, bmwm3gtre46, cobaltss, gti, is300,
punto. Export success proves binding/packing, not runtime completeness.

## Validation

`tests/test_vehicle_runtime.c` checks actual source sidecar loading and pointer
binding, corrupt data rejection, exact-body initialization, source body-before-
producer ordering and transactional rollback after real body integration when a
required producer rejects. Missing source math is rejected before callbacks.
Strict C11 `-Wall -Wextra -Werror -pedantic`, ASan and UBSan pass. These are
integration contract tests; they do not compare a whole vehicle frame to original
PPC. Component original-executable comparisons remain documented individually in
vehicle-mechanical, vehicle-power, player-input and rigid-body reports.

`tools/vehicle_chassis_reference.py` captures original body virtual wrench, Y
correction and angular-velocity commands at8024B014..8024B168 without patching
original instructions. Tilted body-up, dragstyle1.6, bottomout and landing
transitions are covered; all1638 emitted command sequences match float bits.
Source vector scale-and-add rounds multiplication separately before adding; it
must not be replaced by a fused multiply-add.

## Story-owned engine sabotage

The runtime contains an actual MwStoryEngine deadline/blown state and uses the
new engine_step_with_story API. At the exact original802580F8..8025817C stage,
a future deadline modulates **engine angular speed**, not reported RPM: original
single sine of `(deadline-clock)*12*2pi`, then single fused add with omega*.5.
The modulation occurs after torque/reaction construction, before shaft
integration, preserving the earlier RPM sample. Deadline expiry invokes the
source blown-state transition once; the output event is committed after success.
Following frames use source DoThrottle zero for a blown engine. Legacy engine
input/state ABI and wrappers are preserved.2048 unchanged original stage cases
(including real Blow function and observed external event dispatch) and the old
1536-case whole-engine regression pass.

The story-enabled full engine additionally passes1536 unchanged original whole
EngineRacer state cases, including512 continuation steps, for BMW and careerstart.
Every engine field, wheel angular speed, deadline, blown flag and actual blown
event is compared, including future5-second modulation and expired deadlines.
This closes the engine source-order placement gate, not whole-vehicle/world
collision equivalence. The runtime uses source human constructor assist history1
and burnout scale1, and its current steering input-average directly feeds the
original drifting producer.

Collision state now persists the source collision timer, nose/side wall steering
terms and last ground timestamp. SimStart may provide ordered original collision
events through the immutable Produced array. These are applied before the source
Suspension timer decay. Steering runs inside the wheel route bridge after aero
and distribution, then original DoWallSteer setters, then TuneWheelParams. Both
wall setters use the same old common angular snapshot; the later setter wins.
Common wheel velocity and landing angular snapshots remain unchanged by those
body setters, exactly as in the original. Source tickend clears the wall terms.
Ground count uses previous valid contact count, independently of compressed-wheel
count; a steep compressed wheel can have no accepted ground contact.

## Concrete application integration boundary

Keep one stable-address MwVehicleRuntimeParams per selected physical profile and
one MwVehicleRuntimeState per source vehicle. Initialize body quaternion, pose,
velocity, force accumulators, flags, gear, clutch and omega from the recovered
source spawn/constructors. A zeroed body or engine is not a validated replacement.
Use source simulation scheduling at1/60 second. For every tick, provide actual
source_time plus normalized pad inputs, then call mw_vehicle_runtime_step once.
The call order is:

1. before_body_tick: actual OnBeginFrame bookkeeping;
2. original rigid-body integration using previous forces;
3. after_body_tick: original primitive refresh, collision resolution, EndFrame
   force reset/gravity/sleep behavior, with collision events staged privately;
4. produce: current interface/timer/tuning outputs and ordered collision events;
5. original engine, common state, aero, drive distribution, steering and four-wheel
   contacts, then combined wrench/bottomout/landing suffix.

Only after success may the caller commit staged world/event state and apply
ChargeGameBreaker, gear events, wake and EngineBlown. A failing tick preserves
vehicle state/output but cannot roll back arbitrary side effects in caller hooks.
The input-only producer must fill input_present, automatic_enabled, NOS inhibition,
unlimited/boost/tuning providers, actual cached PVehicle::GetAbsoluteSpeed, staging
flags/scalar, steering-wheel mode, Handling/settings presence, GameBreaker, driver
style, damage/wheel-disabled flags, drag-trany boost, yaw/max-speed interfaces,
differential assist settings, and optional Physics::Tunings. Setting the producer
mask63 asserts those bindings; it does not prove them. The runtime supplies
compared body/wheel/raw fields, current engine torque/gear/NOS multiplier and
physical mounts internally. Do not bypass required world/body hooks with no-ops.

Neither a full source-compatible task/world callback implementation nor a
whole-vehicle trajectory comparison has been established here. These remain the
activation gates for replacing the current live driving adapter.
